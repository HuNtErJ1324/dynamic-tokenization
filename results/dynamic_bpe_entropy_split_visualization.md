# Dynamic BPE + Entropy Split 토큰 시각화

**설정:** merges=1000, entropy_threshold=3.0, 한국어 5문장

## 문장 0: 심혈관 질환의 예방을 위해 규칙적인 운동이 필요합니다.

**Stage 0 — Plain Mistral (35 tokens)**
```
▁ 심 [ED 98 88] 관  ▁ 질 환 의  ▁ 예 방 을  ▁ 위 해
▁ 규 [EC B9 99] 적 인  ▁ 운 동 이  ▁ 필 요 합 니 다 .
```

→ 한글 글자 상당수가 3개 byte hex로 쪼개짐

**Stage 3 — Split 후 (59 tokens, 9→59)**

- ` 심혈관` → 14개 byte 조각으로 폭발

**→ 원래 35개보다 24개 더 많아짐. 완전히 역효과.**

## 핵심 관찰

### Dynamic BPE는 잘 작동함
- 평균 35개 byte 토큰 → 9개 어절 토큰 (약 74% 압축)
- 1000번 merge 시도했지만 **25번만에 조기 종료** — 한국어는 이미 byte 수준이라 합칠 pair가 없음

### Entropy가 높은 이유
- Mistral은 이 merged 어절 토큰들을 pretraining에서 본 적 없음
- 따라서 다음 토큰 예측이 불확실 → entropy 높음
- `시스템이` entropy=6.6, `인공지능` 4.8, `운동이` 4.6 등 대부분 threshold 초과
- 비교적 짧거나 단순한 어절(`기반의` 1.4, `예방을` 1.7)은 낮음

### Entropy Split이 실패하는 이유
1. threshold=3.0이면 대부분의 merged 어절이 SPLIT 대상
2. Split 결과가 다시 byte 조각들 → 원래보다 더 많은 토큰
3. 이 byte 조각들을 re-embed → 모델이 의미 있는 생성 불가
4. **no-answer rate 84%** = 숫자를 거의 생성 못 함

### 결론
Dynamic BPE 자체는 유용하지만 (어절 단위 압축),  
merged token 위에서 entropy split을 추가로 하는 것은 역효과.  
threshold를 7.0 이상으로 높이거나 split 단계를 제거하는 것이 나음.
